# openRTLinux v0.2.0

Everything from v0.1.0, plus the things that were missing in daily use.

## New mode: `both - space and hotkey`

A fourth mode sits after *Fix on the hotkey*:

* space/Enter → fixed automatically, exactly like `auto`;
* the fix hotkey then **swaps that word back and forth** — once puts the "wrong"
  spelling back, again fixes it once more.

For the words you *want* to look misspelled: a character name, a password, a joke. It only
ever swaps the word the automatic fix just touched, and only while nothing has been typed
since, so it cannot grab the wrong word.

## Short words are fixed more often (auto)

The word checker alone refuses short tokens — it cannot tell whether two or three characters
are meant to be Thai or English. The automatic path now takes the same second opinion a
deliberate press gets: *the other layout's reading is a real word, and what is on screen is
not*. Measured over both dictionaries (86,999 word/layout pairs):

| characters | before | now |
| --- | --- | --- |
| 2 | 50% | **71%** |
| 3 | 65% | **96%** |
| 4+ | 97% | 99.3% |

**No word typed correctly was flipped — 0% of 86,999.** A single character is still never
guessed without the hotkey being pressed.

## Fixed-word history and Undo

The settings window now lists the **last 20 fixes** (time · typed → corrected), and has an
**Undo the last fix** button. It is enabled exactly while the undo is still safe — nothing
typed since, and the word is still the one the fixer left there — and refuses rather than
mangle anything when it is not. The list lives in the daemon and rides along in `status`;
`undo` on the control socket does the work.

## The window and tray speak Thai or English

A language dropdown at the top of the settings window (`ไทย` · `English` · `Follow system`),
stored as `ui_language`. Behaviour is identical in either language. `openrtlinux-tray --lang en`
overrides it for one run.

## One tray per session

An XDG autostart entry *and* the user service were both starting the tray, which meant two
icons in the panel. Login startup now belongs to the user service alone, and the tray takes a
lock in `$XDG_RUNTIME_DIR` so a second copy exits instead of drawing a second icon.

## Smaller things

* Mode labels are short: `Fix on space or Enter (auto)` · `Fix on the hotkey (manual)` ·
  `both - space and hotkey` · `Off`.
* The daemon reports its own version: `openRTLinux 0.2.0`.
* `docs/PLAN-NEXT.md` records why ghost suggestions / per-app rules are parked.

## Numbers

* **320 unit tests** pass (`cargo test --features linuxos`), upstream's suite untouched.
* A fix takes **13–30 ms** end to end (the daemon prints `applied in N ms` for every fix).
* Verified on Ubuntu 26.04 · GNOME 50 (Wayland) · ThinkPad X13.

## Install / upgrade

```bash
git clone https://github.com/yumehermes8-spec/openRTLinux.git
cd openRTLinux && git checkout v0.2.0
bash packaging/linux/install.sh --release --with-tray
```

Upgrading from v0.1.0 is the same command in the same directory: the settings in
`~/.config/openrtlinux/config.toml` are kept.
