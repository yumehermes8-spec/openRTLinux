# openRTLinux v0.3.0

Everything from v0.2.0, plus the memory the fix hotkey needs - and one fewer
openRTLinux in the app grid.

## A remembered word expires

The fix hotkey reaches for a word that is *already on screen*, so the daemon
remembers it. It now remembers it for a **window**, because this program sees the
keyboard only: no pointer, no window focus, and no idea where the cursor went.

* `recall_seconds = 15` - a word a boundary closed stays reachable for 15 s; after
  that the press does nothing at all (nothing is deleted, nothing is typed).
* `undo_seconds = 60` - the newest fix can be swapped back or undone for a minute;
  a wrong fix is noticed later than a wrong word.
* Escape, an arrow, Home/End, PageUp/PageDown, Delete, or a deliberate layout
  switch forget the word at once: those are the events that say the cursor moved.
* The word *being typed* never expires - it is anchored to the cursor.
* `0` in either key means "never forget" (what it did before this release).

Both windows run on a monotonic clock, so a clock step or a suspended laptop cannot
expire a word early, and the Undo button applies the same guards as the hotkey -
it never lights up for a fix that can no longer be put back.

## The repeated press works

Pressing the fix hotkey more than twice used to chew one character of the text
*before* the word on every press after the first: the hotkey's own Backspace eats a
character of the word when no space was typed, and the swap deleted one too many -
so the word looked like it had been glued onto its neighbour. It now subtracts
exactly what its own keystroke already ate.

In `both` mode a press toggles between the two spellings, and the sentence around
the word stays put: `chord_repeat_tests` presses it ten times in a row and checks
the screen after every one.

## One openRTLinux in the app grid

`openrtlinux.desktop` (the daemon, which is a systemd user service) is
`NoDisplay=true`, so the only openRTLinux in Activities is the tray entry - and it
runs `openrtlinux-tray --window`, so a click lands on the settings window instead
of doing nothing.

## A smaller settings screen

The desktop's own switch key and the command that reads the active layout came off
it. They are still loaded and saved, so `config.toml` keeps the values - they are
simply not shown. What is left is what a typist actually chooses.

## Where it runs

```bash
cd ~/Cursor/righttype-publish
bash packaging/linux/install.sh --release --with-tray
```

Ubuntu (tested on 26.04 + GNOME/Wayland) and read/write access to `/dev/uinput`.
The daemon and the tray run as systemd user services.

335 unit tests pass (`cargo test --lib --features linuxos`).
