# openRTLinux v0.1.0 — first working release

The Linux desktop layer on **RightType**'s OS-free engine, for Ubuntu + GNOME.

## What it does

Watches what you type, notices it is in the wrong keyboard layout, and fixes the word on
the spot — switching Thai ↔ English to match, so you can keep typing.

```
fvdw,h   -> ดอกไม้        แนพพำแะ -> correct
dki[hko  -> การบ้าน       l;ylfu   -> สวัสดี
ก        -> d             869      -> คุต
```

## Highlights

- **Works on Wayland** — reads keys from `/dev/input` (evdev) and types through a virtual
  keyboard (uinput); it does not need XRecord/XTEST, which Wayland apps do not see.
- **Four modes**: `auto` (fix on space/Enter) · `manual` (fix on the hotkey) ·
  **`both`** (fix on space *and* let the hotkey swap that word back and forth — for the
  words you want to keep misspelled) · `off`.
- **The fix hotkey is a choice**: `Shift+Backspace` (default) or `Shift+Spacebar`,
  pick it in the settings window.
- **Works on one character, too** — throttled by measurement: 1 character always, 2–3 on a
  deliberate press, 4+ when the other layout reads as a real word.
- **Fast**: a fix takes **13–27 ms** end to end (its own log says `applied in N ms`).
- **Tray + settings window** (GTK3) with a dry-run switch, and the window itself speaks
  Thai or English.
- **314+ unit tests** (`cargo test --features linuxos`), upstream's suite untouched.

## Install (Ubuntu, no sudo)

```bash
git clone https://github.com/yumehermes8-spec/openRTLinux.git
cd openRTLinux
bash packaging/linux/install.sh --release --with-tray
```

## Not in this release

- ghost suggestions / keyboard palette on Wayland (needs a GNOME Shell extension — a plan
  is in `docs/PLAN-NEXT.md`);
- focused-app rules (on Wayland we cannot see which app has focus — same plan);
- other distributions and desktops (Ubuntu + GNOME is what is tested), and GNOME on X11;
- a `.deb` / Flatpak package.
